# YOLO模型训练与拼图约定

[文档目录](README.md) · [拼图运行契约](拼图自适应与检测方式.md) · [训练仓库](https://github.com/hey-three/yolo-for-han-card-tracker)

## 一个模型覆盖两种输入

当前使用YOLO目标检测，不是OCR。模型输出类别、位置、置信度，布局和牌局逻辑由本项目处理。自定义权重放在yolo/weights/<目录>/best.pt，类别名称必须与config.yaml的yolo_to_card_mapping对应，尤其区分大小王。

建议先建立宽:高=8:5、768×480的统一训练基线，混合原图、开局两区拼图及记牌四区拼图。需要对照更高分辨率时可试1024×640，不能仅凭模型名称推断速度和精度。每个阶段无需单独训练一个模型。

PIL及配置顺序是(W,H)，推理/导出imgsz明确(H,W)=(480,768)。动态/PT支持不同尺寸，静态ONNX/TensorRT必须与导出形状一致。当前已有960目录及静态导出不代表已经导出成768×480。

## 数据和标注

- 先按牌局/视频分训练、验证、测试，再生成拼图，避免同一帧原图与拼图跨集合。
- 使用与运行时一致的用户ROI、严格像素边界、固定初始比例和代表性在线比例。覆盖两阶段、原图、无底牌和结算画面。
- 标注随Tile缩放和偏移变换；保留内部重叠的完整副本，正确处理切口碎片。不能把YOLO预测直接当作人工真值。
- 覆盖两行、长牌组、纵长大小王、底牌变淡、选牌抬起等实际变化。玩家框外内容不靠算法补救。
- 原图等比填到精确8:5可以减少微小宽高差导致stride额外填边；必须同步变换标签。

Ultralytics普通检测训练的imgsz使用单整数，例如imgsz=768与rect=True；不能把推理支持的二元尺寸直接套作训练参数。批次stride和验证pad仍可能改变内部shape，需要查看真实批次。依据：[训练说明](https://docs.ultralytics.com/modes/train/)、[预测说明](https://docs.ultralytics.com/modes/predict/)，并已复核既有安装代码。

## 当前证据

固定初始比例来自三张1284×804参考图的实际普通单牌框，不来自大区域框；统计、模型哈希及例外见[设计决策](设计决策.md)与[排查和验证](排查与验证.md)。这些不是训练真值，也不构成总体准确率或200ms保证。当前没有因这些建议启动训练、改权重或重导出引擎。
