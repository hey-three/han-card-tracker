# YOLO模型训练与拼图约定

[文档目录](README.md) · [拼图运行契约](拼图自适应与检测方式.md) · [训练仓库](https://github.com/hey-three/yolo-for-han-card-tracker)

## 一个模型覆盖两种输入

当前使用YOLO目标检测，不是OCR。模型输出类别、位置、置信度，布局和牌局逻辑由本项目处理。自定义权重放在yolo/weights/<目录>/best.pt，类别名称必须与config.yaml的yolo_to_card_mapping对应，尤其区分大小王。

同一个模型混合原图、开局两区拼图及记牌四区拼图，每个阶段无需单独训练。不同模型可以使用不同的固定输入尺寸，方形、横矩形、竖矩形均按各自配置处理；不能仅凭目录名或模型名称推断输入、速度和精度。

## 模型目录必须附带输入配置

新增或替换模型时，必须同时放置 `yolo/weights/<目录>/best.pt` 和同目录的 `model_config.yaml`，不能只复制权重或只修改目录名。参考[配置模板](../yolo/model_config.example.yaml)：

```yaml
model: YOLO11n
weights: [best.pt, last.pt]
input:
  width: 960
  height: 608
  resize: letterbox
  rect: false
```

- `model` 仅为描述，真正网络由所选 `best.pt` 决定；`weights` 若提供，必须包含所选文件名，不要求同时提供 `last.pt`。
- 宽高必须为正整数并与32步长对齐；不接受字符串、布尔值、非整数、非正数和隐式向上补齐。有特殊步长的模型还会在加载后校验实际步长。
- 仅支持等比缩放补边 `letterbox`；固定输入要求 `rect: false`，关闭预测的最小矩形补边。省略这两个字段时按上述默认值处理；不支持拉伸。
- PIL/拼图画布为 `(W,H)`，Ultralytics 推理和导出 `imgsz` 为 `(H,W)`。例如配置960×608，拼图就生成实际960×608像素，模型请求 `(608,960)`，不是只固定长宽比。
- 原图、开局二区、记牌四区、同帧整图复查均使用同一配置。裁片等比缩放，严格用户边界、内部重叠保护、按原坐标去重保持不变；切换模型重建规划/尺度缓存。
- 配置仅在加载模型时读取一次，修改后切换到其他模型再切回或重启；逐帧不读取YAML、计算权重哈希或导出。
- 已有文件损坏或字段非法会明确报错，不静默换尺寸。仅对完全缺少配置的旧模型保留兼容：动态/PT请求旧768×480，原图仍可能最小补边；静态后端沿用旧导出形状。新增模型不依赖此后备路径。

## 静态后端和首次导出

CPU优先ONNX，CUDA优先TensorRT FP16，失败回退PT并保持配置尺寸。转换结果直接保存在原PT同目录：例如 `yolo/weights/<模型>/best.pt` 旁生成 `best.onnx` 或 `best.engine`，分别附带 `best.onnx.meta.json` / `best.engine.meta.json`。记录权重SHA-256、目标高宽、batch=1、精度、环境、设备及导出摘要；仅文件存在不足以复用，没有匹配记录的旧导出需重新生成。

只在源目录内的短期 `.model-export-*` 工作区复制PT并导出，实际绑定/步长验证通过后原子替换同名导出和校验记录，工作区自动清理；原始PT不改。失败保留旧文件或留下无法通过摘要验证的记录，回退同尺寸PT。目录不可写也会回退PT，不改用其他缓存目录。根目录 `model_cache` 已删除，不搬迁旧内容，不再创建；下次加载需要时重新转换。

首次转换可能较久，后续相同条件复用同目录结果。主窗口顶端在启动或模型/设备切换期间显示“正在加载模型”和“首次可能较久”，悬停说明ONNX/TensorRT首次转换；不受普通布局提示开关影响，完成/失败恢复对应状态，不解锁检测或设置请求。校验记录和临时工作区不上传Git，也不占诊断配额；打包需包含PT及配置，静态导出跨机器仍须校验身份。真实验证范围见[排查与验证](排查与验证.md)。

requirements明确锁定onnxruntime==1.26.0、onnx==1.21.0和onnxslim==0.1.94。启动时比较ORT的Python包装和原生库版本，混装时先报告并回退PT。导出显式simplify=False，ONNX随后由应用调用已安装的onnxslim简化、保留元数据并校验；TensorRT自行优化。这样避免Ultralytics按CUDA可用性另外自动安装onnxruntime-gpu，CPU/GPU两个运行库不重叠安装。缺少导出依赖时回退并提示，不在程序运行中自动安装。

## 960×608训练代码复核

用户提供的自定义 `DetectionTrainer.build_dataset()` 在 `rect=True` 时覆盖 `dataset.batch_shapes[:] = (608,960)`。按本项目锁定的Ultralytics 8.4.6源码，读取样本时用该形状作为 `rect_shape`，LetterBox优先采用它；关闭 `multi_scale` 时不再随机改变批次尺寸。这一方式能固定训练输入，仍应在训练环境核对真实首批 `batch['img'].shape == (B,3,608,960)`。当前只审阅代码，没有启动训练。

训练器创建的验证加载器也经过这个覆盖，并被训练内验证和最后验证复用；单独重新执行原生 `model.val()` 则不会自动读取本项目旁置文件或自定义训练器，须另行保持固定验证数据尺寸。源码依据：[数据集取样](https://github.com/ultralytics/ultralytics/blob/v8.4.6/ultralytics/data/base.py)、[训练器](https://github.com/ultralytics/ultralytics/blob/v8.4.6/ultralytics/models/yolo/detect/train.py)、[LetterBox](https://github.com/ultralytics/ultralytics/blob/v8.4.6/ultralytics/data/augment.py)、[验证器](https://github.com/ultralytics/ultralytics/blob/v8.4.6/ultralytics/engine/validator.py)。

脚本开头描述YOLO11s，但 `MODEL_PATH` 指向名为 `yolo11n.pt` 的预训练文件，两者应核对一致；真正网络仍以权重内容为准，目录名及旁置 `model` 字符串不能改变结构。960×608的宽高比为30:19（约1.579），不是精确8:5；608和960均为32的倍数。

960×608比960×960少36.67%输入像素；比旧请求768×480多58.33%。固定网络最终输入相同时，先拼更大的同比例图再缩小不会减少网络运算，直接生成目标像素画布通常可少一次整图缩放；先拼更小图可能损失单牌细节。像素减少不等于耗时同比减少，需分别测预处理、推理、后处理、截图及通信。

## 数据和标注

- 先按牌局/视频分训练、验证、测试，再生成拼图，避免同一帧原图与拼图跨集合。
- 使用与运行时一致的用户ROI、严格像素边界、固定初始比例和代表性在线比例。覆盖两阶段、原图、无底牌和结算画面。
- 标注随Tile缩放和偏移变换；保留内部重叠的完整副本，正确处理切口碎片。不能把YOLO预测直接当作人工真值。
- 覆盖两行、长牌组、纵长大小王、底牌变淡、选牌抬起等实际变化。玩家框外内容不靠算法补救。
- 原图等比填到精确8:5可以减少微小宽高差导致stride额外填边；必须同步变换标签。

Ultralytics普通检测训练的imgsz使用单整数，例如imgsz=768与rect=True；不能把推理支持的二元尺寸直接套作训练参数。批次stride和验证pad仍可能改变内部shape，需要查看真实批次。依据：[训练说明](https://docs.ultralytics.com/modes/train/)、[预测说明](https://docs.ultralytics.com/modes/predict/)，并已复核既有安装代码。

## 当前证据

固定初始比例来自三张1284×804参考图的实际普通单牌框，不来自大区域框；统计、模型哈希及例外见[设计决策](设计决策.md)与[排查和验证](排查与验证.md)。这些不是训练真值，也不构成总体准确率或200ms保证。未启动训练、未修改源权重；输入/ONNX缓存的真实验证和未测项以排查文档为准。
