## 原图完整性与预览来源

已经复现旧桌面BitBlt会把覆盖游戏的设置/预览窗口一起读入。当前优先PrintWindow完整渲染目标窗口，失败/黑输出才回退可见桌面；最小化或未选窗口返回未知，不以空标题匹配其他窗口。DPI上下文按物理像素读取并恢复。

受控四角图证明原图直接进入模型边界，宽/竖/方图等比预览均保留四角；遮挡测试证明优先窗口渲染不混入覆盖窗口。用户随后反馈实际问题已修复。不能据此保证所有GPU窗口、皮肤或屏外场景都支持窗口渲染；桌面回退必须完整可见无遮挡。

预览标题标此帧实际原图/拼图、像素尺寸及桌面回退，指接口输入图，不冒充letterbox后的网络张量。切换确认或当前无帧清旧图，旧代次不能清新图。设置打开期间后台识别继续，仍保留用户手动暂停及busy保护。

## 设置与牌局的关键覆盖

- 固定两帧底牌存在性，不比较牌面/张数；第二帧才累计手牌，按FRAME_LENGTH确认。空、未知、暂停中断开局累计，新局确认前保留上局显示。
- 命名自动布局保存完整窗口标题，长标题省略不撑宽；命名、覆盖拒绝、取消、目标未运行时恢复均覆盖。模式点击即用，各自历史成功后原子保存，失败恢复；尚未回执时点回原模式也不能漏提交。
- 手动编辑器重开载入本机参考图和五区，同窗重截图映射草稿；取消/失败保留内容，保存名称与运行时切换独立。自动与手动列表复用可靠图标点击处理。
- 标题栏赞赏入口跳到同一个SettingsDialog的赞赏页，复用打开暂停/关闭恢复；已打开设置只跳页，不建立另一个二维码页面。赞赏页签流光、波动尚未实现。
- 完整诊断是观察旁路，关闭/录制/暂停不改变首扣和牌账；8帧、64MiB与磁盘配额、缺帧恢复和旧局清理沿用原回归。首扣缺张仍是检测质量待查项，见[V4.3.2问题回归](V4.3.2问题回归与诊断机制.md)。

## 已知限制与未测项

- 本次不进行完整实战、长时间热机、真实GPU/TensorRT、打包、全新环境安装或Android验收；CPU静态图、构建或单测通过均不能替代这些验证。
- 如果下一局底牌在RESET_TIME之前出现，连续空区计时会取消，可能漏分局；目前没有新增手牌重发等辅助信号，按用户要求只讨论，未改结束业务规则。
- 自动布局适用本家在下、两家左右的常见界面，歧义/未知暂停，不能恢复未观测的此前出牌。不承诺所有软件、皮肤和模式兼容。
- 日志/逐帧证据可以说明发生了什么，不等于自动定位模型错误根因；自动回放和一键导出未实现。

## 保存材料与排查

终端debug_mode是即时输出；show_current_screenshot是实际接口输入预览；完整诊断才保存每次输入/标注、状态前后、缓存及可关联编号。脱敏后保留涉及帧的JSON、输入图、标注与前后邻帧，避免只看最终计数推断漏检来源。

| 现象 | 先检查 |
|---|---|
| 无法启动或服务故障 | 顶部错误、终端堆栈、Python/包版本和权重文件，修正后重启 |
| 有图但不开局 | 上方底牌是否连续两帧可见、区域是否正确、手牌是否非空稳定 |
| 原图正常而拼图不正常 | 基本设置→手动框选→检测方式对照，核对用户框、内部切口、初始比例和实际输入 |
| 两行出牌归属或顺序错误 | 对应原图、各框原坐标与归属；对照两行fixture，不能按类别字母重排 |
| 首扣缺牌或本家出牌后疑似重复扣 | initial_hand、remaining delta与确认前后帧；本家只记历史，不反推修正 |
| 诊断暂缓或暂停 | 独立diagnostic_status、events缺口、队列/字节预算和磁盘配额；识别继续 |
| 模型首次加载较久 | 顶部加载提示、PT旁导出及meta、输入尺寸/依赖/设备身份，不能直接信任同名旧文件 |
