# 排查问题与验证证据

[文档目录](README.md) · [提交问题](https://github.com/hey-three/han-card-tracker/issues/new/choose)

## 现在可以留下什么

- debug_mode：终端区域牌面与部分阶段计时输出；不是完整结构化状态日志。
- show_current_screenshot：实际YOLO接口输入的JPEG预览，可能是原图、拼图或记牌中复查的原图；这不等于已保存实际输入。
- save_debug_images：ImageSaver统一保存games_images/row/game_N/N.png原图和games_images/yolo/game_N/N.png最终原坐标标注图。
- 当前每局最多1000张、最近3局；达到上限不继续存，创建新局可清理旧目录。需要反馈时及时复制所需材料。
- 牌局目录主要随开局建立；运行时重新启用保存且无活动目录也可能建目录。局号/保存序号不是稳定的推理帧ID。

目前未持久化每次模型调用的输入和标注，也没有每帧完整状态前后快照、状态变化原因及回放导出。因此仅凭现有成对图无法解释所有扣牌错误；完整逐帧诊断是待讨论功能。

## 排查顺序

| 现象 | 先看什么 |
|---|---|
| 无法启动/服务故障 | 状态栏错误、终端堆栈、Python和包版本、权重文件；修正后重启识别 |
| pip找不到torch的cu121包 | Python版本、官方cu121索引及requirements，不仅看Python语法最低版本 |
| 有图但不开局 | 实际YOLO输入是否有上方底牌、区域是否正确、置信度、手牌是否非空稳定 |
| 原图能识别、拼图不行 | 高级设置切换对照；核对用户框、切口、初值和实际输入，不能假设程序会扩框 |
| 两行出牌分错玩家 | 保存对应原图和最终标注，说明归属、首次出现还是已有锚点；附布局模式 |
| 本家打牌没有再减 | 先核对统计口径；本家初始手牌已扣，本家出牌不应重复扣 |
| 结束后还显示旧记录 | 设计如此，下一次底牌出现开局才刷新 |
| 预览或保存缺帧 | 区分未传图、无可靠结果、未建活动目录、容量上限和真实保存失败 |

反馈请带源码提交、模型目录或SHA、后端、窗口大小、布局模式、手动原图/拼图偏好、帧长度和结束时长，以及期望与实际。可选图片先遮盖账号和聊天信息；不要上传个人完整配置、敏感截图或权重来替代最小复现。

测量权重：yolov11s_imgsz_960/best.pt，SHA-256为e2419bb59102168fde02324fe6981a583e4300c524645897c967f521605397b7。普通牌参考框高38.581787109375px，底牌26.1554、手牌54.8069、上下家约38.5、本家出牌46.1480；大小王长框不用于该参照。

完整实战序列、真实截图循环、CUDA/ONNX/TensorRT、exe打包、Android以及干净安装锁定依赖均没有由上述记录证明通过。早期跨Qt测试曾出现0xc0000374，补充窗口销毁及配置隔离后复跑通过，但没有Qt内部C++根因证据。

历史本机验证使用过Python3.14与额外本地依赖，和requirements锁定版本不同。临时日志与用户图保存在tests/.tmp，不作为公开、跨机器可直接取得的测试数据。

```powershell
python -X faulthandler -B -m unittest discover -s tests -v
python -B -m doctest core/frame_packing.py core/square_packing.py core/auto_layout.py
python -B -m utils.preview_staged_packing
```

常规测试不加载真实YOLO。合成预览默认写docs/assets/v431-current；提供私有图片时仅允许写tests/.tmp，避免误提交。
