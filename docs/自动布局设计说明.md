# 斗地主自动布局

## 使用方法

在“设置 → 基本设置 → 自动布局…”选择游戏窗口，关闭设置后开始检测。无需截图框选五个牌区。程序会保存一个名为“自动布局 · 窗口标题”的布局，之后可在布局列表直接选择；原有手动布局仍可使用。

请在开局前启动。初始化需要合法完整的 17/20 张本家手牌及三家尚未出牌的画面，稳定阈值为 `max(3, FRAME_LENGTH)`。底牌可缺失、只识别到一两张或牌面闪烁，不参与手牌稳定签名。已检出的其他出牌组会阻止开局。仅凭牌框无法绝对排除“中途恰剩十七张且出牌已清空”的画面，因此仍应在开局前启动，不能宣称能从任意中途画面恢复历史。

当前实现面向本家在下方、两家在左右、底牌在上方的常见三人斗地主界面。它使用相对位置先验和从当前画面学习的参照，仍需要用各软件的真实 YOLO 输出验证，不能据模拟框测试宣称兼容所有软件。

当前 V4.3 自动模式从校准到跟踪始终整图推理，不生成候选裁片。只有用户手动指定的五区才进入固定 640×640 保护拼图；旧独立路线开关退出界面，配置仅作兼容。详见 [V4.3 更新说明](V4.3更新说明.md)。

## 数据流

```text
窗口截图 → YOLO 全图识别 → 归一化 CardBox
                            ↓
                  顶边聚行、间隔拆组、相邻行合组
                            ↓
                  开局校准 / 已知牌区跟踪
                            ↓
                  LayoutObservation（已知区域、未知状态）
                            ↓
                  原 Tracker 扣牌和连续帧确认
```

核心算法位于 `core/auto_layout.py`，不加载 torch、YOLO 或 Qt，可用确定的检测框独立测试。模型仍只负责识别牌面及坐标。

## 分组与归属

1. 坐标除以截图宽高归一化。按检测框顶边聚成行，行内按横向空隙拆成牌组，单张牌也是合法牌组。所有尺度以检测目标自身的宽高为依据，兼容牌角框的模型。
2. 相邻行在纵向足够接近、横向范围对齐时合并。以原始行建图，避免合并后的双行高度继续扩大容差。不能把单行的位置评分当作已确认身份：若上下行的牌框宽高相近、末行包含在上行横向范围内、同侧对齐且对应牌列一致，即使初始评分把短末行判为本家，也先合并后按整组归属。近期本家手牌减少、此前单独稳定出现的本家整手牌属于更强的独立证据，可阻止与明确的对手行合并。
3. 初始化寻找下方 17/20 张牌组，确认牌面多重集和边界连续稳定。上方中央小牌组最多三张，可分散检出，作为可选底牌；其余牌组阻止初始化。主流程使用配置中的牌面张数上限过滤非法开局。完成后调用 `DoudizhuTracker.initialize_from_layout()`，本家初始手牌只扣一次。
4. 出牌归属使用整组的锚点：左家用左边、右家用右边、本家用中心；纵坐标使用第一行顶边。长牌组跨过画面中线也不会被逐牌拆到两家。
5. 初始出牌锚点由实际手牌边界与窗口相对几何推导，底牌不再充当必要位置锚点。当前桌面上界先验为手牌顶边的 0.18 倍，左右/本家的纵向先验分别为桌面间距的 0.38/0.70；这些是通用相对位置起点，不是按游戏名称查表的模板。后续只根据连续稳定出牌学习锚点。组长变化、第二行缩短或为空时，不删除已学习区域。
6. 候选归属按横纵尺度化距离评分；距离过大、前两名过于接近、同一区域出现不相容的多个组时，三家出牌均标记未知，暂停本帧出牌更新。不会强行选择最近区域。
7. 短暂保留手牌减少的牌面作为本家出牌证据，用于消除位置边界附近的歧义。相同牌组近距离移动到另一区域时不立即改身份；同牌面持续移动时中断确认缓存，位置稳定后再确认。

初始参数是实现起点，尚不是跨软件测量结果：同一行顶边容差为较小牌高的 0.45 倍，相邻行距离为约 0.55～1.65 个牌高；归属评分上限 2.4、第一二名间隔至少 0.45。参数集中在自动分析器内部，不增加用户配置负担。

### 首次跨行出牌的回归案例

用户提供的 JJ 斗地主截图中，下家出了上行八张、下行两张 4。现有模型在该图片上检测到了全部十张出牌；旧算法将上行判给下家、下行判给本家，再用“两个玩家”作为禁止合并的条件。第一次出牌没有学到锚点时容易触发，且误归属的下行还会污染本家锚点。几轮后已有实际出牌参照，通常不易触发。

`tests/fixtures/right_wrapped_play.json` 保存该图片用项目现有权重在 CPU 上提取的真实 YOLO 框，不包含原图。原图本家只有十五张手牌，因此测试补入两张模拟开局牌来建立同一几何参照；这不是该局真实开局的重建。回归覆盖首次八加二、末行单张、左右镜像、已学习位置、真实本家独立出牌的保护、错位不合并、抖动和六帧确认。它验证单帧检测的连续回放，不代表已验证完整实战动画。

## 空区域、未知区域和扣牌

`LayoutObservation.regions` 的三种情况：

| 表达 | 含义 | Tracker 行为 |
|---|---|---|
| 有键且列表非空 | 已确认区域内有牌 | 收集连续帧，稳定后记录 |
| 有键且列表为空 | 当前观测中该区域为空 | 连续稳定后允许作为相同出牌的空帧过渡 |
| 没有该键 | 无法确定、画面缺失或动画影响 | 清除该区域确认缓存，保留出牌历史及空帧标志 |

自动模式通过 `known_regions` 显式传递这些信息。手动模式在有效结果时显式传入全部五区，失败则传空集合，不再使用底牌门禁。全图无检测不等于所有出牌区已经出现空帧，不制造“再次出相同牌”的过渡；独立的换局监测只累计成功截图且模型返回有效结果后的无牌帧。截图失败、结果为 None 或 boxes 缺失中断累计；空拼图先整图复查，每截图仅累计一次。

自动模式按牌面多重集生成稳定顺序，因此同一手出牌从一行重排为两行，不会因为列表顺序改变再次扣减。本家后续出牌只记录，上家/下家稳定出牌才扣减，统计口径见 `斗地主记牌设计说明.md`。

## 重新校准和验证边界

- 等比例缩放使用归一化坐标继续跟踪。截图长宽比相对校准基准改变超过 5% 时只重新校准几何，保留当前牌局；重新定位不能再次扣初始手牌或清空历史。
- 底牌改变、变淡或隐藏不触发换局。两种模式仅在至少 `max(3, FRAME_LENGTH)` 帧有效全图无牌，且持续至少 `RESET_TIME` 秒后结束。某家剩零张不参与，结束只进入等待，不操作游戏软件。
- 结束后保留上一局统计及历史，清理内部确认和自动几何；下一组合法完整 17/20 张手牌连续稳定后一次性刷新。结束前已确认全图无牌，允许下一局恰好同手牌。
- 未见任何出牌之前，原十七张完整保留且增至二十张连续稳定时，只补扣新增三张。已见出牌或已有历史后不再改写初始手牌。
- 同一窗口内复杂重新排版、底牌持续可见且没有产生全图无牌边界的切局，仍可能需要手动重置。窗口移动本身不改变窗口内坐标。
- 不确定期间已经消失的出牌无法从后续画面恢复；状态提示“暂停更新”不代表完整记牌仍有保证。应从下一局重新初始化后核对统计。
- 自动测试覆盖三家单张、跨中线长牌组、两行末行单张、换行重排、手牌减少证据、空区保持、歧义隔离、移动动画、隐藏底牌、初始手牌换行、缩放和真实 Controller/Tracker 接入。尚需在安装模型依赖后录制完整对局，用真实检测结果回放验证。
