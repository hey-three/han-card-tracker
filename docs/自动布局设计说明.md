# 斗地主自动布局

[文档目录](README.md) · [手动拼图](拼图自适应与检测方式.md) · [计数规则](斗地主记牌设计说明.md)

## 适用范围

设置 → 基本设置 → 自动布局 → 新建布局，在紧凑弹窗选择目标窗口并命名，点击“保存并使用”；后台确认成功后保存mode:auto及空layout。已有自动布局单独列在下拉框，下次直接选择；铅笔编辑名称/目标窗口，垃圾桶删除。长标题仅显示省略，实际保存完整窗口标题；编辑时窗口暂未运行也能保留原关联。点击自动/手动模式会立即使用该模式上次成功应用的布局，失败恢复原模式；没有布局先提示新建。运行时根据当前画面学习几何，不按游戏名称查固定区域表；生成参照不写回配置。

自动模式始终整图推理，适用于常见本家在下、对手在左右、底牌在上方的三人斗地主。建议从开局前启用，不能从中途画面还原先前历史，不宣称兼容所有软件。

## 底牌范围独立学习

底牌区域横向始终为截图15%～85%，即居中70%，不随本家手牌位置、补检大小王或选牌抬起而移动。尚未学习时，候选检测框中心须位于窗口顶部25%以内；这是排除中央翻牌的搜索上限，不是固定的最终高度。

第一帧按候选框下沿加半个框高提出高度，取最大值并封顶25%。连续两帧提议差不超过屏高3%时，取二者较大值确认。只有一张底牌也可学习，牌面或张数可以变化；提议不稳时继续用初搜范围，学习不额外延迟业务开局。未知、空画面、暂停打断尚未确认的学习；确认后本局不因少识别牌或短时漏检收缩，也不因本家手牌变化调整。

实际底牌归属只比较牌框中心是否在当前矩形中，不再追加手牌中心距离或宽高约束。预览“底”框显示同一个矩形，即使底牌为空也保留。顶端计数栏被模型误认成牌仍可能干扰；超出居中70%或顶部初搜上限的布局不保证适用。

截图尺寸改变时重学底牌高度，等比缩放不清牌账或其他已学习几何；新局、布局切换、显式重置也重新学习。长宽比改变超过5%沿用全局重定位规则。手动布局继续严格使用玩家保存的底牌框，不应用本规则。

## 分组与归属

1. YOLO框按截图尺寸归一化，顶边聚行，行内空隙拆牌组，单张也是牌组。
2. 同侧/列对齐、尺度相近的相邻行先合并，再按整组归属。不能先把短末行判给本家，随后以不同玩家身份阻止合并。
3. 上方底牌先发布存在性，Tracker固定连续两帧有牌才开局，不比较牌面/张数；第二帧才作为业务手牌的第1帧。几何学习的手牌观测与业务确认缓存独立，几何initial只是定位通知，不能绕过Tracker门槛或首扣。
4. 左家用左边、右家用右边、本家用中心及第一行顶边作锚点；长牌组跨中线不能逐张拆给两家。
5. 初始桌面位置从手牌和窗口相对几何推导，底牌不是必要位置锚点，但底牌存在性仍是业务门禁。中央翻牌动画不视为上方底牌到位。
6. 候选过远、前两名接近、同区出现不相容牌组时返回未知；不强行选择最近区域。近期手牌减少和此前稳定的独立本家出牌可阻止错误并行合组。

底牌阈值在core/bottom_region.py，其余阈值在core/auto_layout.py，尺度来自牌框自身。它是几何先验与在线锚点，不是经过所有皮肤测量的模板。

## 空区与未知

| 返回 | 含义 |
|---|---|
| 有键且非空 | 已知区内有牌 |
| 有键且空列表 | 当前明确为空 |
| 没有键 | 归属或画面不可靠 |

Controller通过known_regions传给Tracker；未知中断未确认序列，不抹已确认历史或制造重复出牌所需的空区过渡。底牌消失的帧数和时长判断遵循[牌局生命周期](斗地主记牌设计说明.md)。

## 重新定位与回归

截图长宽比相对参照改变超过5%只重新校准几何并保留本局记录。底牌变化牌点不换局；复杂重排、持续有底牌的切局或不确定期间丢失出牌，可能需要在下一局重置。

tests/fixtures/right_wrapped_play.json保存一张实际截图的模型框，回归覆盖首次八加二、末行单张、左右镜像、移动、抖动、换行重排和六帧确认。该截图初始手牌不足，测试使用补充模拟牌建立几何；不是重建原局真实开局，也不是完整动画验收。

偏右底牌回归使用tests/fixtures/auto_bottom_right.json的去标识坐标：2879至2887帧补检大王、手牌中心变化时，已识别的3必须始终属于底牌。该材料存在缺帧，仅验证几何问题，不称为整局回放或已经恢复此前漏记的QQJJ1010。
