# V4.3 续更：手动五区方形拼图与统一保留历史换局

更新日期：2026-10-27。以下为当前行为，替代此前“自动校准后可选桌面带拼图”的试验路线。

## 问题与结果

此前自动候选保留了过多桌面背景，固定 640 画布并未完成有效区域压缩；手动五区反而一直走整图。旧手动模式还依赖底牌、超时立即清屏，自动模式存在按玩家零张结束的另一条判断。

本次由布局唯一决定路线：**自动布局全程整图；手动布局全五区保护拼图**。独立实现长条多候选重叠切分、统一比例 MaxRects 方形装箱、原坐标去重、同帧回退。布局不变时复用规划及画布。原有五区内容全部覆盖，外围尤其下方保留余量，避免旧中心点矩形截断竖排大小王和第二行。

## 使用与兼容

- 选择“自动布局”：始终整图推理，包括校准成功后。
- 选择已框好五区的手动布局：首帧即可拼图，最终画布固定 640×640；不为每家分别跑模型。
- 切口残片有完整副本时按原图位置去重；未知归属、完整框冲突、无完整副本或空拼图均复查当前同一原图。最终仍保存成对原图及原坐标标注，不将中间图当原图保存。
- 旧 `packed_inference` 配置保留兼容，不控制路线。高级设置以说明文字替代开关；设置按钮提示显示耗时、模型调用次数、源覆盖、含重叠面积、画布留白和块数。
- 动态/PyTorch 拼图请求 640，静态后端保持原导出输入；回退恢复整图输入。已有模型可运行，但拼图分布需真实准确率验证。
- 用户个人 `config/config.yaml`、既有权重、私人截图不属于本次提交。

## 开局、结束和刷新

手动与自动都需要尚无出牌、合法完整的 17/20 张手牌连续 `max(3, FRAME_LENGTH)` 帧稳定确认，底牌不是开局必要条件。手动区域缺结果不能被当作稳定空区。发牌阶段未见出牌时，十七增二十只补扣三张；已有出牌不得改写初始手牌。

结束**只**依据连续有效原图检测无任何扑克牌，同时满足：

1. 连续帧数至少 `max(3, FRAME_LENGTH)`；
2. 从首个有效无牌帧开始的持续时间至少 `RESET_TIME` 秒（界面“无牌结束时长”，现有个人配置 3 秒）。

拼图空结果先整图复查，每张截图只累计一次。出现任何牌、截图/结果缺失或暂停恢复都会中断无牌连续性。普通超时、底牌缺失和“某家可能/确实剩零张”均不结束。`remaining_by_player` 及其地主分配推算已移除。

结束时只清内部确认缓存并进入等待，**牌数与出牌历史保持上一局**。新完整手牌稳定后才一次性初始化并刷新。显式点击重置仍立即清屏。全图无牌边界成立后允许下一局发到完全相同的手牌。自动几何重新校准继续保留历史。若结算画面仍持续检出扑克牌，此规则会继续等待全图无牌，不另用零张兜底。
