# V4.3：Windows 保护拼图试验链路与分阶段性能观测

## 本次解决的问题

整张窗口直接送入模型时，大量背景也进入推理输入。简单把手牌长条从中间切开，又可能切断牌角标记；直接把重叠区的输出相加，会把同一张牌重复计数。此前截图预览增加牌区参数后，部分旧调用也失去了兼容性。

本次新增一条用户可关闭的保护拼图路线：自动布局先用整图完成严格开局校准，随后对保守候选区规划拼图；长条中心两侧保留重叠保护，结果还原到原窗口坐标后去重，再交给现有布局与记牌逻辑。不通过放宽 17/20 张门槛掩盖漏牌或重复牌。

## 使用方式与默认行为

在“设置 → 高级设置 → 识别路线”选择：

- **整图（默认）**：沿用完整窗口推理。
- **保护拼图（试验）**：自动布局完成校准后尝试拼图。手动布局和未校准阶段仍用整图。

配置字段为 `packed_inference`，布尔值，旧配置缺省 `false`。通过现有请求回执和原子保存流程应用；保存失败不误报成功。关闭试验选项即可恢复整图，不需要改模型或重装程序。

正常布局状态后会附加识别路线或整图复查原因。鼠标停在“设置”按钮上，可查看上次检测的截图、拼图准备/检查、模型调用、坐标恢复/去重、预览编码、布局记牌/保存、子进程整轮及调用次数。主进程的完整请求往返耗时仍显示在标题栏。

## 具体实现

### 1. 中心切分和重叠保护

`core/frame_packing.py` 不依赖 torch、Qt 或第三方 APK。对宽长条中心切分，两侧共享保护区；当前内部起点为原图宽度的 4%，自动布局会参考实测牌框中位宽度适当增大，窄裁片最多保留其宽度四分之一作为单侧保护。

裁片保持原始像素比例，使用 Pillow 的底层裁剪/粘贴，枚举少量排列以减少最长边和画布面积。模型继续负责等比例缩放和填充，不把牌面横纵分别拉伸。画布尺寸不变时复用 RGB 图像缓冲；不缓存、拼接不同帧的识别结果。

### 2. 原图坐标恢复与去重

每块记录原图裁剪矩形和画布偏移。检测框按图块恢复到同一原图坐标，再处理跨块重复：

- 相同原图位置、相同类别且重叠充分的跨块检测只保留一个；不同位置的同点数牌保留。
- 同一位置的跨块类别冲突不能只按置信度选择，要求整图复查。
- 触及裁片边缘的残片，仅在有完整副本覆盖时丢弃；没有完整副本则复查。
- 落在画布间隔、跨越图块或无可靠检测时，丢弃拼图结果。

去重后的结果重新构造为原图尺寸的 Ultralytics Results，供现有手动/自动解析接口使用。最终调试截图保存仍经 `ImageSaver`，原图与标注图保持相同坐标和尺寸；不把拼图误存为原始截图。

### 3. 保守候选区与同帧回退

首版不盲目缩到“上一手出牌”的小框。校准后保留完整宽度的出牌桌面带，并保留下沿手牌区域和底牌候选区；出牌带一直延伸到手牌上方，为向下展开的第二行保留空间。保留现有整组归属、一行/两行多重集确认和手牌减少证据。

`core/packed_pipeline.py` 在以下情况回到同一张原始截图推理：

- 首帧、未校准、窗口尺寸变化或用户切换路线。
- 切边缺少完整副本、类别冲突、异常图块边界、空或失败的拼图结果。
- 128×128 灰度参照检查发现候选区外变化。
- 连续尝试达到 `2 × max(3, FRAME_LENGTH)` 次，或距上次整图超过 2 秒。

低分辨率变化检查仅是复查触发器，不能证明区外一定没有牌，也不是通用牌区检测器。复杂重新排版、动画和短暂出牌仍需真实序列验证，因此默认不启用试验路线。

### 4. 单模型、输入尺寸与计时

- 续更后的实际拼图画布固定 640×640，所有裁片用统一比例放入并填灰；源区域仍自动适配。`Tile.project/unproject` 将缩放与偏移纳入坐标恢复。旧版仅在模型预处理中填充固定方形的做法已替换。
- 复用当前模型，不新增权重、训练任务或模型下载。
- PyTorch / 动态后端的拼图调用尝试 640 输入；静态 ONNX / TensorRT 保留原导出尺寸，不自动重导出，也不承诺减少其网络计算量。
- 缓存首次整图输入配置，拼图之后明确恢复原输入尺寸及矩形填充策略，防止 640 污染后续 960 整图回退。
- CUDA 调用前后同步，计时覆盖真正完成的 Ultralytics 调用；没有 CUDA 的本机只验证了该同步契约，未验证 GPU 性能。
- `yolo_ms` 统计本轮所有模型调用，包含失败补查成本。Ultralytics 调用内部包含其自己的预处理和后处理，不能称为纯网络前向。
- `Response.performance` 只传不可变快照数据，不传图像；旧代次数据及指标一并丢弃。

### 5. 预览兼容修复

为截图预览的区域和名称参数提供空值默认行为，修复 4 个原有调用错误。缺少牌区信息时显示原图，不伪造边界，也不重新打开用户已经关闭的预览。

## 本次没有直接实施的方案

- 只看下半屏就开始扣牌：当前仍用整图校准，需完整手牌及无出牌的开局证据；续更已取消底牌必要条件。
- 彻底停用或低频检测手牌：当前归属逻辑依赖手牌变化，先保留每帧证据。
- 细分三家独立小框、通用颜色牌区定位：缺少跨软件覆盖及动画证据，先采用较宽桌面带。
- 引入 MNN / TFLite / NCNN、INT8、NPU：属于平台与模型适配，需要独立等价性和真机验证；未复制第三方实现。
- 320/512 新模型训练、安卓移植及手机速度承诺。

先保留整图对照和可关闭的试验入口，在真实序列上确认正确性及回退比例，再决定默认配置和后续优化。

## V4.3 续更：底牌可选、固定画布和自动等待下一局

### 行为变化

- **自动适配继续保留。** 不增加游戏名称→区域模板表，初始出牌参照改由实际手牌与窗口相对几何推导，随后学习稳定出牌位置。完整合法 17/20 张手牌连续稳定且尚无其他出牌即可开局；底牌缺失、零星识别、变淡或牌面变化不再阻塞或单独重置牌局。
- **结束先保留显示。** 连续 `max(3, FRAME_LENGTH)` 帧成功截图、模型返回有效结果且无牌，或某家有确切剩余零张时，结束内部跟踪。牌数与出牌历史保持上一局；新完整手牌稳定后再一次性替换。不是替游戏点击“再来一局”。
- **旧画面与未知不算新局。** 确认出完后，旧开局手牌及结束时残留的同一组完整手牌不能立即重复初始化。确认全图清空后允许下一局恰好同手牌。截图失败、None 结果不累计无牌并中断连续性；拼图补查两次只算一帧。普通超时和窗口比例变化不清空历史；比例变化仅重新定位。
- **张数有依据才判零。** 本家二十张时对手各十七张；本家十七张时保留两种地主分配，某家累计超过十七张可排除其中一种。未知、计数矛盾或负牌数不算零，不能将全局按牌点的剩余总数当作某家剩余。
- **发牌阶段允许增补。** 尚未见任何出牌、连续确认原十七张完整包含在二十张中时，只补扣新增三张，不重置整局；已有历史后禁止改写初始手牌。
- **画布固定。** 规划器仍自适应选区和保护切口，渲染输出固定 640×640，114 灰边，整套图块统一比例缩放，保留像素取整信息用于严格逆变换。当前仍保留全宽出牌带和每帧手牌，未实现细小三家 ROI 或手牌降频。
