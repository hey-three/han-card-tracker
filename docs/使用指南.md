# 安装与使用

[文档目录](README.md) · [配置参考](配置参考.md) · [排查问题](排查与验证.md)

## 安装依赖

本项目依赖 Windows 的窗口截图接口。源码使用Python 3.10+语法，但不能据此推断当前全部固定依赖可在任何3.10+环境安装。建议先用Python 3.11/3.12独立环境；已有其他项目环境不要直接覆盖。

```powershell
git clone https://github.com/hey-three/han-card-tracker.git
cd han-card-tracker
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install torch==2.5.1 torchvision==0.20.1 torchaudio==2.5.1 --index-url https://download.pytorch.org/whl/cu121
python -m pip install -r requirements.txt
python -m pip check
python main.py
```

命令中的PyTorch组合与现有requirements一致，索引依据[官方旧版本安装说明](https://pytorch.org/get-started/previous-versions/)。不安装CUDA Toolkit并不等于没有CUDA运行依赖；GPU还取决于驱动与实际可用设备。无NVIDIA GPU时可在设置中选CPU，不把TensorRT视为必需项。

此次维护没有从零安装上述锁定环境。现有回归环境与requirements版本不完全相同，不能把已有测试结果当作固定依赖安装成功。遇到依赖或NumPy桥接错误，请保留完整错误与版本，见[排查与验证](排查与验证.md)；不要仅凭“安装完成”认定推理可用。

## 模型文件

仓库跟踪了YOLO11n/s/m模型子目录的best.pt及部分ONNX导出。模型列表按子目录扫描，不支持直接把best.pt放在weights根目录：

```text
yolo/weights/<模型名称>/best.pt
```

自定义模型需保留牌类映射，参见[训练约定](模型训练与拼图约定.md)。文件名中的imgsz_960是模型目录标签，不代表任何运行路线都使用960输入。n/s/m的速度与精度需要在本机测量，不直接宣称哪个“最准”。

## 选择布局

### 自动布局

“设置 → 基本设置 → 自动布局…”选择窗口。建议开局前启用，等待上方底牌出现与非空手牌稳定。自动模式整图识别，不需要手工矩形；它适用于常见本家在下、两家在左右的界面，不能从中途画面恢复此前出牌。

### 手动布局

“设置 → 基本设置 → 可视化编辑”选择窗口、截图并框选五区：本家手牌、本家出牌、上家出牌、下家出牌、地主底牌。预览校验后保存。两行出牌和大小王是否完整落在框内由用户确认；算法不向外扩边。

![五个区域的布局编辑示意](../images/layout_debug.png)

在“设置 → 高级设置 → 手动布局检测方式”选择拼图或原图。所有手动布局共用这一偏好，自动模式不受它影响。开局前拼图一直只取底牌和手牌，首次扣手牌后才换四区。

## 核对第一次计数

上方底牌任意一张即可开局；非空手牌连续稳定后扣一次。不要求17/20张，但稳定漏检会使初始化偏少，因此仍需核对识别完整性。开始记牌以后不因手牌数量变化自动补扣。

底牌持续消失满足帧数及时间阈值后，程序保留上一局数据等待下一局。新底牌出现才刷新。手动“重置记牌器”会立即清空，适合明确需要重来时使用。

## 显示与排查开关

| 设置 | 用途 |
|---|---|
| 输出调试日志 | 终端输出区域结果与部分计时信息 |
| 完整诊断 | 后台保存实际YOLO输入/各调用标注、原图、状态与确认进度；达到限额会暂停诊断 |
| 保存游戏截图 | 按现有局目录保存原图与最终原坐标YOLO标注图 |
| 实时显示YOLO输入 | 独立窗口显示真正送入接口的原图或拼图 |
| 显示耗时 | 标题栏显示模型调用和整轮往返耗时 |

四项排查功能独立。关闭预览窗口或按Esc会保存关闭偏好；退出主程序只隐藏预览，不更改该偏好。完整诊断保存证据，自动回放尚未实现。

日常关键事件日志自动轮转。需要复现错误时短时开启完整诊断；设置页显示后台实际状态，故障原因在状态栏也始终可见。排除原因后关闭再开启会创建新会话，旧材料保持不完整标记。目录、容量和性能边界见[诊断记录](诊断记录.md)。
