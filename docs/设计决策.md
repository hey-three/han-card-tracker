# 需要长期保留的设计决策

[文档目录](README.md) · [更新记录](../CHANGELOG.md)

这里记录理由与已取消路线，具体运行参数以对应专题文档和源码为准。

| 决策 | 原因与取舍 |
|---|---|
| 先验证Windows，再考虑Android迁移 | 手机性能截图不是Windows基线；不能把桌面测试说成手机验收。当前仓库不提供APK |
| 命名预设与使用状态分开，模式即选即用 | 自动布局保存名称和完整窗口标题，复用原window_layouts；last_layouts只记成功使用，两种模式分别恢复，后台失败回退，避免首项看似选中却未应用 |
| YOLO只负责视觉，布局与记牌分层 | 检测错误、归属错误和扣牌错误能分别验证；不要把牌局规则写进模型 |
| 三阶段：底牌固定两帧，非空稳定手牌扣一次 | 连续两帧底牌区有任意牌才开局，不比较牌面/数量；第二帧才累计手牌第1帧，手牌按FRAME_LENGTH确认，不要求17/20张 |
| 保留底牌作为业务门禁 | 中央翻出的底牌可能被误当对手出牌；上方到位后再开局，底牌持续消失才结束 |
| 自动结束先保留旧显示 | 用户希望结算时还能查看；下一次底牌连续两帧确认才刷新，显式重置仍立即清空 |
| 只扣本家初始手牌和对手出牌 | 本家出牌再扣会重复；底牌若属于本家初手也不能单独再扣 |
| 自动布局整图、手动可选原图或拼图 | 自动模式没有可靠的预先区域，不能假装裁掉未定位区域；手动已有五框，可阶段化省背景 |
| 开局两区、扣手牌后四区 | 必须先完成初手扣减再去掉手牌，未观测手牌不能当作空区；开局无底牌仍只两区，不额外整图校准 |
| 玩家负责选区，不向框外扩展 | 用户明确取消四周/下沿保护边；严格只取框内像素，人工外边界不等于算法内部切口 |
| 内部切口重叠与原坐标去重 | 长条可拆成紧凑拼图，但重复牌必须按位置消除，不能按牌点去重。内部残片需完整副本，人工边缘残片有完整副本时也优先去重 |
| 固定画布与自适应内容分开 | 按所选模型model_config.yaml固定实际像素宽高，缺文件旧模型才后备768×480；裁片按当前框和权重重排，保持比例，不旋转或拉伸 |
| 初始比例允许固定，之后学单牌尺度 | 底牌1.652110、手牌0.703958、本家出牌0.836045、上下家约1是用户确认初值。不能按大区域框大小估计牌大小；无底牌不试探加大 |
| 学习复用现有检测，不增加全图预热 | 三帧普通牌中位高度、底牌目标大12%、10%迟滞；初值让首次可运行，学习结果仅属于当前布局上下文 |
| 已知空与未知严格区分 | 失败、动画或归属不明不应推进空帧/结束，也不能造成连续两手相同牌误扣 |
| 模型输入契约统一 | 画布(W,H)、推理及导出(H,W)来自同一配置；静态绑定必须匹配，导出保存在原PT同目录，以权重/尺寸/环境/摘要校验身份，不信任旧同名文件；首帧拼图不污染整图复查 |
| 不从面积或短样例推断速度与准确率 | 原图和拼图若同张量，卷积主体开销接近；裁背景主要给牌面分配像素。42次静态调用不代表200ms或完整实战 |

## 明确停止使用的方案

- 不再以完整17/20张稳定手牌作为开局硬门槛，不再17→20自动补扣。
- 不按某家余牌为零或全图无牌作为额外独立结束条件，不在结束瞬间清空旧显示。
- 不在自动模式用宽桌面带拼图，不在手动模式固定全五区推理；不强制某个方形或矩形尺寸，按所选模型的旁置配置确定。
- 不替玩家扩框，不因未识别底牌而先整图识别几次，不在无底牌时逐级放大试探。
- 没有复制第三方APK源码、图片或权重。第三方静态分析启发过图像打包、缓冲复用和有界队列的讨论，不据此推断对方实机后端或准确率。

旧讨论和重复类图已从当前文档树移除，完整原文仍可由Git历史恢复。

## 诊断采用有界旁路

日常关键事件日志长期保留，通过大小轮转控制磁盘；完整逐帧诊断默认关闭，开启后仅建一个长驻保存线程。复制必须发生在可复用输入被下一帧覆盖前，压缩/绘制/落盘放后台；不承诺零开销。名额和字节预算包含正在写的一帧，超载暂停并明确标记不完整，避免无限积压或悄悄丢帧。当前局及崩溃未封口证据不自动覆盖；按局分目录，默认1GiB磁盘额度可在高级设置调整。后台可清理已封口旧局，无法安全腾出容量则暂停；详见[诊断记录](诊断记录.md)。
