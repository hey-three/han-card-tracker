# 斗地主记牌与牌局生命周期

[文档目录](README.md) · [架构](架构与数据流.md) · [设计决策](设计决策.md)

## 统计口径

剩余牌数 = 整副牌按牌点的数量 − 本家首次确认手牌 − 已确认的对手出牌。

它不是三位玩家各自剩余张数，也不等于画面上当前可见的牌数。本家手牌初始化只扣一次，本家后续出牌只记历史；底牌不另扣一次。对手稳定出牌才扣除。

例如整副牌有4张A，本家初始拿1张，显示剩余A为3；本家打出该A仍为3，上家再打1张才变为2。正确取得17/20张初始手牌且尚无对手出牌时，总数分别为37/34；这是核对示例，不是开局数量门槛。

## 三阶段

| 状态 | 条件与动作 |
|---|---|
| WAIT_BEGIN | 等待上方底牌区有任意一张；下一次开局才刷新上一局显示 |
| HAS_STARTED | 底牌已出现；等待非空合法手牌连续FRAME_LENGTH帧稳定 |
| STARTED_RECORD_CARD | 首次手牌已扣除，处理确认出牌；手动拼图下一帧换四区 |

当前规则源自V3三阶段，经用户确认放宽为任意一张底牌当前帧开局，并修复空手牌也可能稳定通过的问题。不要求完整17/20张，不后来自动补扣17→20。初始稳定漏检仍会少扣，必须核对检测质量；不能为规避漏检暗中恢复被取消的数量门槛。

## 确认与重复牌

BaseCardTracker按区域保存最新FRAME_LENGTH帧，全部一致才确认。阈值调小下一帧可生效，调大需等足够帧。本家出牌只记录，上下家出牌扣牌。has_found_empty表示空区过渡，用于区分连续两手相同牌；持续显示一手不能重复扣。

自动布局按牌面多重集排序，同一手从一行重排成两行不应重复扣。区域不存在表示未知；存在且空列表才表示已知为空。未知清未确认缓存，但保留已经记下的历史，不能伪造空帧过渡。

## 暂停、结束与新一局

- 底牌区无牌立即暂停记录并清未确认序列。
- 已知为空连续至少max(3,FRAME_LENGTH)张截图，而且从首张起持续RESET_TIME秒，内部结束进入等待。
- 未知结果、截图失败、暂停/恢复中断累计，不按成功的空帧处理。同帧拼图与复查只能算一帧。
- 三家余牌归零、底牌牌面变化、单纯截图长宽比变化、全图无牌不作为额外独立结束条件。
- begin_waiting保留旧remain_cards/show_cards。下一次底牌出现开局刷新，再等稳定非空手牌扣一次。用户显式重置立即清空。

主要入口：core/games/doudizhu.py的observe_bottom_presence、get_cards_number、on_game_started、on_start_recording和process_played_cards。Controller不因自动几何定位的initial通知直接扣牌。

回归见tests/test_tracker.py、test_round_lifecycle.py、test_wrapped_ownership.py。构造框或静态帧回放能验证规则，不证明目标软件完整动画时序和实战不漏牌。
