# 斗地主记牌与牌局生命周期

[文档目录](README.md) · [架构](架构与数据流.md) · [设计决策](设计决策.md)

## 统计口径

剩余牌数 = 整副牌按牌点的数量 − 本家首次确认手牌 − 已确认的对手出牌。

它不是三位玩家各自剩余张数，也不等于画面上当前可见的牌数。本家手牌初始化只扣一次，本家后续出牌只记历史；底牌不另扣一次。对手稳定出牌才扣除。

例如整副牌有4张A，本家初始拿1张，显示剩余A为3；本家打出该A仍为3，上家再打1张才变为2。正确取得17/20张初始手牌且尚无对手出牌时，总数分别为37/34；这是核对示例，不是开局数量门槛。

## 三阶段

| 状态 | 条件与动作 |
|---|---|
| WAIT_BEGIN | 上方底牌区连续两张截图都有任意牌才开局，固定两帧；第一帧仍保留旧显示，不累计手牌 |
| HAS_STARTED | 第二张有底牌的截图作为手牌第1帧，等待非空合法手牌连续FRAME_LENGTH帧稳定 |
| STARTED_RECORD_CARD | 首次手牌已扣除，处理确认出牌；手动拼图下一帧换四区 |

沿用V3三阶段，底牌存在性现固定连续两帧确认；不比较两帧的底牌张数或牌面。底牌已知为空、未知、截图失败或暂停会打断开局累计。第一帧不加入手牌缓存，第二帧才开始；手牌阈值仍由设置FRAME_LENGTH控制。设为3帧时，最早第4张连续有效截图才完成首扣。不要求完整17/20张，不后来自动补扣17→20；稳定漏检仍可能少扣，不能暗中恢复数量门槛。

## 确认与重复牌

BaseCardTracker按区域保存最新FRAME_LENGTH帧，全部一致才确认。阈值调小下一帧可生效，调大需等足够帧。本家出牌只记录，上下家出牌扣牌。has_found_empty表示空区过渡，用于区分连续两手相同牌；持续显示一手不能重复扣。

连续帧确认和已记录牌组对比使用牌点多重集（Counter，包含重复张数），同一手从一行重排成两行不重复扣；不再把用于稳定比较的类别排序当作显示顺序。历史按确认帧的画面顺序显示：先上行再下行，每行从左到右；既不按字母也不按牌点大小重排。区域不存在表示未知；存在且空列表才表示已知为空。未知清未确认缓存，但保留已经记下的历史，不能伪造空帧过渡。

## 暂停、结束与新一局

- 底牌区无牌立即暂停记录并清未确认序列。
- 已知为空连续至少max(3,FRAME_LENGTH)张截图，而且从首张起持续RESET_TIME秒，内部结束进入等待。
- 未知结果、截图失败、暂停/恢复中断累计，不按成功的空帧处理。同帧拼图与复查只能算一帧。
- 三家余牌归零、底牌牌面变化、单纯截图长宽比变化、全图无牌不作为额外独立结束条件。
- begin_waiting保留旧remain_cards/show_cards。下一次底牌连续两帧确认开局才刷新，第二帧起等待稳定非空手牌扣一次。用户显式重置立即清空。
