# 斗地主记牌设计说明

## 1. 统计口径

本项目从本家视角统计剩余牌。`remain_cards` 表示：从整副牌中，排除本家的初始手牌和已经确认的对手出牌后，各牌点的剩余数量。

因此，本家的牌在开始记牌时就已经从统计范围中排除了。本家后来把这些牌打出去，不会使统计范围内的牌再次减少。

## 2. 为什么自己的手牌只扣一次

对任意牌点 `r`，记牌公式为：

```text
remain_cards[r]
    = 整副牌中 r 的数量
    - 本家初始手牌中 r 的数量
    - 上家累计确认打出的 r 的数量
    - 下家累计确认打出的 r 的数量
```

本家当前手牌会持续出现在游戏画面中，而且会随着本家出牌而减少。持续识别到手牌，不代表每一帧都需要重新扣减；手牌数量减少，也不代表应当把已经打出的本家牌加回去。

正确流程是：

1. 开始记牌时，确认本家初始手牌，并扣减一次。
2. 后续画面中的本家手牌不再重复扣减。
3. 本家出牌只追加出牌记录，不再扣减剩余牌数。
4. 上家和下家的出牌经连续帧确认、去重后，扣减相应牌点的数量。
5. 新一局重置到整副牌数量，再重新初始化。

例如，一副牌有 4 张 A，本家初始持有 1 张 A，则初始化后的剩余 A 为 3。本家随后打出这张 A，剩余 A 仍为 3；上家再打出 1 张 A，剩余 A 才变成 2。本家出牌时再扣一次，会重复扣减同一张牌。

在初始手牌完整且尚无对手出牌的前提下：本家为农民、持有 17 张牌时，初始化后剩余总数为 37；本家为地主、持有 20 张牌时，初始化后剩余总数为 34。地主底牌若已包含在本家的 20 张初始手牌中，也不能再单独重复扣减。

## 3. 当前代码对应关系

- `core/games/doudizhu.py` 的 `on_start_recording()`：扣减本家初始手牌。
- `core/games/doudizhu.py` 的 `process_played_cards()`：本家区域 `self` 不扣牌，上家和下家区域扣牌。
- `core/base_tracker.py` 的 `run_game()`：从等待开始推进到开始记牌；正常一局中，初始化手牌的回调只在进入记牌状态时执行一次。
- `core/base_tracker.py` 的 `_process_all_played_zones()`：确认出牌、维护显示记录，并通过空帧过渡处理连续两次出相同牌的情况。

“本家初始手牌只扣一次，本家后续出牌只记录”的设计符合上述统计公式。代码审查不能仅因本家手牌持续可见，或本家出牌没有再次扣减，就把它判定为 bug。

## 4. 设计原则与识别时序边界

上述公式以正确取得本家初始手牌为前提。初始手牌何时完整显示、地主底牌何时可见、识别是否暂时漏检，是另一层问题，需要结合目标斗地主软件的实际画面时序验证。

先前审查中的“连续空手牌后出现 17 张手牌”是构造输入下的代码复现，并未证明这一时序会在目标游戏的实际使用中发生。该复现说明代码遇到这种输入时的行为；它不否定只扣一次初始手牌的设计，也不能单独作为目标游戏中已发生故障的证据。

本次仅记录统计设计与验证边界，不调整现有识别、状态转换或扣牌逻辑。
